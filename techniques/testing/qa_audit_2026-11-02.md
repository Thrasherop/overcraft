## 4. Lessons for QA (why these got through)

- **No hero was played against the data's UI list.** The HUD was built hero by hero from frames and the Kiriko template.
  Nobody listed the data's UX presenters per hero and ticked them off. The HUD layer map (ability bar `v40845`, centre
  `v40843`, hero reticle `v11821` / `v40842`, world `v36881`) should go in `techniques/game-data/reading_game_data.md`
  beside the 0727 lesson, and be read before any new hero's HUD.
- **Shared code was tuned for Kiriko and never re-read per hero.** `track()`'s Swift Step logic, the kill-feed source
  test and `targetMarker()`'s key are Kiriko-shaped. Each new hero needs a pass over every shared HUD path.
- **Kill-feed and kill-marker checks need a real kill with every ability,** not one kill per hero. Seven heroes have an
  ability whose kill never sends the kill marker.
- **Dev packs differ per worktree.** Hand play on `next` without the full pack hides missing-art bugs, and a full pack
  hides fallback bugs. Play both.
