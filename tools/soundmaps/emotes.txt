# The heroes' emote sounds: one sound event per 02C sound of an emote clip's animation effect (08F), built the way its
# Wwise Play event builds it, and one event per voice stimulus (078) of the clips. Same format as kiriko.txt /
# lucio.txt / jetpack_cat.txt; paths are under E:\Overwatch Archive\extracted\154088\ (build 154088). The client
# plays each event at its component's start time while the emote runs (the clip components are in each rule's
# comment). Read offline (Overwatch and Battle.net closed), Kiriko and Lúcio 2026-10-27, Jetpack Cat 2026-10-28;
# research: E:\Overwatch Archive\research\emote-sounds\ (scripts\: emote_fx.py the clip components, ww.py +
# wwfull.py the Wwise trees, emote_events.py / gen_emotes.py this file; sounds.json what the client needs: loops,
# lengths, audience). Files extracted with DataTool's own WEM->OGG (extract_banks.py) into ExtraSounds\<Hero>\Emotes\;
# a sound shared with an earlier hero's emotes is read from that hero's folder (Jetpack Cat's Listen Up and Mic Drop
# ones from Lúcio's). Nothing here has been listened to: each rule says what the data shows (H read), what is
# inferred (M) and what is a guess (L).
# Gains: Wwise volume + make-up gain (the middle of random ranges) summed from each file up through its containers
# and actor-mixers, plus its output bus chain (Init bank 1E818). Unlike the ability maps, ONE offset per hero is added
# to every emote rule (not one per rule), so the sounds of an emote keep the game's balance with each other; it brings
# the loudest single layer to -1 dBFS. Voice lines are copied as extracted (no gain). Pitch: cents (+ the middle of a
# random range) as a speed factor (*). Low/high-pass filters, random pitch / volume per play, fades and Seek (random
# start points) are not reproduced; sounds.json lists the loops and cuts for the client.
# Audience (M): every emote 02C has STUSound audience 2 (3D: the hero's third-person copy, also what the emoting
# player hears, the camera being third-person). Wwise state group 8E (030 008E, id 3941853002) picks copies: its state
# 00FC (4014561839) unmutes 2D copies (+90 dB) and mutes their 3D twins (-90 dB) (Listen Up), and leaves Orion Dance's
# music audible while state 00F5 (411699078) and five others mute it (-99 dB). Read as: 00FC = the emoting player's
# own view, 00F5 = the other players in a match (00F5 also lifts the footstep mixer +16 dB and the cloth mixer +7 dB,
# as Overwatch makes others' footsteps loud). So 'own' rules take state 00FC's values, all others 00F5's. Which
# context each state is, is not in the data read (Wwise states are global, set by the game): M.
